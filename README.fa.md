# کاغذ آنلاین

[English](README.md)

یک وب‌اپلیکیشن برای نوشتن و به‌اشتراک‌گذاری سند، که از پایه برای زبان فارسی
ساخته شده است. رابط کاربری راست‌به‌چپ است، ویرایشگر با فونت وزیرمتن می‌آید و
تنظیمات تایپوگرافی و ترازبندی، متن فارسی را حالت پیش‌فرض در نظر می‌گیرند؛ نه
چیزی که بعداً به پروژه اضافه شده باشد.

کاربر سندی را در ویرایشگر می‌نویسد، مشخص می‌کند چه کسی آن را ببیند، و لینکش را
به دیگران می‌دهد. سند می‌تواند عمومی باشد، خصوصی باشد، یا عمومی اما پشت رمز
عبور. هر کاربر هم می‌تواند تعدادی از سندهایش را در صفحه پروفایل خودش منتشر کند.

## چه کارهایی انجام می‌دهد

**حساب کاربری.** ثبت‌نام با ایمیل و رمز عبور همراه با تأیید ایمیل (اختیاری)، و
ورود با OAuth. کاربر موقع ثبت‌نام نام کاربری انتخاب می‌کند؛ این نام هم در سمت
مرورگر و هم در سمت سرور اعتبارسنجی می‌شود، پیش از ساخته شدن حساب از نظر آزاد
بودن بررسی می‌شود، و در برابر فهرست رزرو‌شده در فایل `reserved-usernames.json` رد
می‌شود تا نام‌هایی مثل `admin` یا `dashboard` در اختیار کسی قرار نگیرد و با آن‌ها
خودش را جای مسئول سایت جا نزند.

**نوشتن.** ویرایشگر TipTap با تیترها، فهرست‌ها، نقل‌قول، بلوک کد، لینک، تصویر،
فایل پیوست، ضخیم، کج، زیرخط، خط‌خورده، رنگ متن، هایلایت، فونت، اندازه فونت و
ترازبندی چپ، وسط و راست. سند هنگام تایپ و با کمی تأخیر خودش ذخیره می‌شود.

**اشتراک‌گذاری.** تعیین وضعیت هر سند (عمومی یا خصوصی)، امکان گذاشتن رمز عبور
روی سندهای عمومی، و یک گزینه جداگانه برای انتشار سند در پروفایل؛ یعنی سند در
پروفایل نویسنده دیده شود ولی جای دیگری فهرست نشود.

**فایل‌های پیوست.** می‌توان به سند فایل پیوست کرد. فایل‌ها در یک باکت خصوصی
Supabase Storage ذخیره می‌شوند و فقط از طریق یک API قابل دسترسی‌اند که اول
دسترسی به سند را بررسی می‌کند. نام فایل هم همراه با خود سند رمزنگاری می‌شود.

**داشبورد.** نمای شبکه‌ای و فهرستی، جستجو، فیلتر بر اساس وضعیت انتشار، و
جابه‌جایی سندها با کشیدن و رها کردن که ذخیره می‌شود.

**پروفایل.** برای هر کاربر یک صفحه عمومی در `/[username]` با سندهای منتشرشده،
شمارنده بازدید و پسند هر سند، و مجموع آن‌ها در کل پروفایل. صاحب پروفایل هم یک
ویرایشگر تب‌دار دارد برای نام نمایشی، بیوگرافی، وب‌سایت، موقعیت مکانی، تصویر
پروفایل (با مرحله برش تصویر)، نام کاربری و رمز عبور.

**رمزنگاری.** عنوان و محتوای سند، رمز عبور سند و نام فایل‌های پیوست، پیش از
رسیدن به دیتابیس با AES-256-CBC رمزنگاری می‌شوند.

## پشته فناوری

| لایه | انتخاب |
| --- | --- |
| فریم‌ورک | Next.js 15 با App Router |
| رابط کاربری | React 19، Tailwind CSS، و shadcn/ui روی Radix |
| ویرایشگر | TipTap نسخه ۲ |
| بک‌اند | Supabase — پستگرس، احراز هویت، فضای ذخیره‌سازی |
| زبان | TypeScript با حالت strict |
| میزبانی | هر جایی که Next.js اجرا شود؛ Vercel ساده‌ترین راه است |

سرویس بک‌اند جداگانه‌ای وجود ندارد. Server Component‌ها صفحه را رندر می‌کنند،
Client Component‌ها تعامل را مدیریت می‌کنند، و کارهای نیازمند دسترسی سطح بالا
در route handler‌های زیر `app/api/` انجام می‌شود.

## نصب و راه‌اندازی

به Node.js نسخه ۲۰ یا بالاتر و یک پروژه Supabase نیاز دارید. پلن رایگان کافی است.

```bash
git clone https://github.com/Arshnme/kaghaz-online.git
cd kaghaz-online
npm install
```

برای ساخت دیتابیس، فایل `database/01-schema.sql` را در SQL Editor پنل Supabase
اجرا کنید. این فایل جدول‌ها، ایندکس‌ها، سیاست‌های Row Level Security، توابع،
تریگرها و باکت‌های ذخیره‌سازی را می‌سازد. در صورت تمایل بعد از آن
`database/02-sample-data.sql` را اجرا کنید تا چند کاربر و سند ساختگی برای تست
داشته باشید.

سپس متغیرهای محیطی را تنظیم کنید:

```bash
cp .env.example .env.local
openssl rand -base64 32   # ENCRYPTION_KEY
openssl rand -base64 32   # JWT_SECRET
```

آدرس و کلیدهای Supabase را وارد کنید و بعد:

```bash
npm run dev
```

برنامه روی `http://localhost:3000` بالا می‌آید.

راهنمای کامل، از جمله تنظیمات احراز هویت Supabase که اشتباه در آن‌ها رایج است،
در [docs/deployment.md](docs/deployment.md) آمده است.

## متغیرهای محیطی

| متغیر | ضروری | توضیح |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | بله | به شکل `https://<project-ref>.supabase.co`. برای بارگذاری تصاویر از پروژه Supabase هم استفاده می‌شود |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | بله | عمومی است و به مرورگر می‌رود؛ چیزی که از داده‌ها محافظت می‌کند Row Level Security است |
| `SUPABASE_SERVICE_ROLE_KEY` | بله | فقط سمت سرور. Row Level Security را دور می‌زند، پس نباید هرگز به مرورگر برود |
| `ENCRYPTION_KEY` | بله | رمزنگاری داده‌های سند. اگر گم شود یا عوض شود، سندهای قبلی خوانده نمی‌شوند |
| `JWT_SECRET` | بله | امضای توکن نشست |
| `GOOGLE_SITE_VERIFICATION` | خیر | در صورت تنظیم، به‌صورت متا تگ رندر می‌شود |
| `YANDEX_SITE_VERIFICATION` | خیر | مانند بالا |


## ساختار پروژه

```
app/                    صفحات App Router و route handler‌های API
  api/                  دسترسی به داده با سطح دسترسی بالا
  dashboard/            فهرست سندها
  editor/[id]/          ویرایشگر
  [username]/           پروفایل عمومی و سندهای عمومی
components/
  ui/                   اجزای پایه shadcn/ui
  auth/ dashboard/ editor/ public/
lib/                    ابزارهای سمت سرور: رمزنگاری، توکن، کش، اعتبارسنجی
database/               فایل‌های SQL برای ساخت ساختار، داده نمونه و کوئری‌های مدیریتی
docs/                   مستندات معماری و استقرار
hooks/                  هوک‌های React
public/                 فایل‌های ثابت و manifest وب‌اپ
```

[docs/architecture.md](docs/architecture.md) مدل داده، جدول مسیرها و تقسیم
مسئولیت میان دو لایه کنترل دسترسی را توضیح می‌دهد.

## نکات امنیتی

پیش از انتشار، دانستن این سه نکته لازم است.

**کلید service role به‌طور کامل Row Level Security را دور می‌زند.** این کلید در
route handler‌های `app/api/auth/`، `app/api/profile/`، `app/api/documents/` و
`app/api/files/` استفاده می‌شود. به همین دلیل این handler‌ها خودشان مالکیت رکورد
را بررسی می‌کنند و به RLS تکیه نمی‌کنند. کلید باید سمت سرور بماند.

**`ENCRYPTION_KEY` بدون مهاجرت قابل تغییر نیست.** با عوض کردن آن، عنوان و محتوای
همه سندهای قبلی و نام فایل‌های پیوستشان خوانا نمی‌مانند، و تابع `decrypt` به‌جای
خطا دادن، متن رمزشده را همان‌طور برمی‌گرداند. این رفتار عمدی است تا یک رکورد خراب
کل صفحه را از کار نیندازد. از کلید نسخه پشتیبان نگه دارید، جایی که سال بعد هم
در دسترس باشد.

**رمز عبور سند رمزنگاری می‌شود، نه هش.** موقع باز کردن سند، رمز رمزگشایی و مقایسه
می‌شود. این کار عمدی است چون برای مقایسه به متن اصلی نیاز است، اما یعنی هر کسی
که `ENCRYPTION_KEY` را داشته باشد می‌تواند رمز هر سند اشتراکی را بخواند. نگذارید
کاربران برای این رمزها از رمز عبور مهم خودشان استفاده کنند.

`JWT_SECRET` و `ENCRYPTION_KEY` مقدار پیش‌فرض ندارند. اگر تنظیم نشده باشند،
عملیاتی که به آن‌ها نیاز دارد خطا می‌دهد و بی‌سروصدا از یک مقدار پیش‌فرض استفاده
نمی‌کند؛ چون مقدار پیش‌فرضی که در یک مخزن عمومی کامیت شده باشد، دیگر راز نیست.

## وضعیت پروژه

پروژه کار می‌کند و در حال استفاده است. چند بخش هم صادقانه ناتمام‌اند:

- فایل‌های آیکونی که `app/layout.tsx` و `public/manifest.json` به آن‌ها اشاره
  می‌کنند در مخزن نیستند. فهرستشان در [public/README.md](public/README.md) است.
- مسیرهای `/terms`، `/privacy` و `/about` در فرم ثبت‌نام لینک شده‌اند و در
  sitemap هم آمده‌اند، اما صفحه‌شان هنوز ساخته نشده است.
- مسیر `app/api/analytics/track/route.ts` فقط یک stub است که لاگ می‌گیرد و موفقیت
  برمی‌گرداند، و مسیر `app/api/check-username/route.ts` کار می‌کند اما هیچ‌کس آن را
  صدا نمی‌زند؛ فرم ثبت‌نام آزاد بودن نام کاربری را مستقیم از Supabase می‌پرسد.
- جدول‌های `document_comments` و `user_follows` در ساختار دیتابیس هستند اما رابط
  کاربری ندارند.
- Supabase پکیج `@supabase/auth-helpers-nextjs` را که این پروژه از آن استفاده
  می‌کند کنار گذاشته و جایش `@supabase/ssr` را توصیه می‌کند. مهاجرت به آن
  مهم‌ترین کار باقی‌مانده در این پروژه است. توضیحش در
  [docs/architecture.md](docs/architecture.md) آمده است.
- تست خودکار وجود ندارد. CI فقط lint، typecheck و build را اجرا می‌کند.
